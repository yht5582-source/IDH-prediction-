# HD-AI｜透析中低血壓預警系統 v1.1

[互動網頁（GitHub Pages）](https://yht5582-source.github.io/IDH-prediction-/)

目前具有 60 床總覽、病人與每次療程獨立識別、常規/緊急透析管理、CAN 風險紀錄、常規每小時與異常加測血壓、規則型提醒。**本網站使用合成資料，非已驗證 AI 模型，禁止輸入真實病人資料。**


## v1.1 XGBoost 模型訓練中心（公開示範版）

- 「XGBoost 訓練中心」頁籤提供**合成資料預檢**：常規療程、病人數、量測數、符合完整 60 分鐘觀測期的預測點與首次有紀錄 SBP <90 的陽性點。
- 可產生及下載研究訓練計畫 JSON，列明預測目標、訓練對象、時間外驗證、資訊安全前提；**此 JSON 不是訓練完成的模型**。
- 「檢查能否啟動訓練」只顯示尚未有授權院內後端，不會執行 XGBoost 或捏造 AUROC、預測機率。
- 目前前端合成資料只有少量療程，且並非完整臨床特徵。預檢是教育用途，不能作為臨床樣本數或模型效能驗收。
- 訓練基礎程式：`ml/train.py`；實際執行必須在院內安全伺服器、以核准的歷史資料及資料品質程序為前提。護理長不用安裝 Python。
- 正式一鍵訓練需要院內後端實作：登入／授權、訓練工作佇列、資料快照與血壓時間戳記稽核、時間外驗證、校準、模型註冊、版本審核與模型回滾；公開 Pages 不接收真實病人資料。

## v1.0 合成資料即時回放：護理長操作模式

新增 `realtime.js`，在首頁可使用「開始合成回放」「前進 15 分鐘」「自動播放」「暫停」「重設回放」。播放每 2 秒前進 15 個**模擬分鐘**，只在合成時鐘到達實際紀錄時間時揭露該筆資料；**未量測期間不會虛構血壓**。顯示班別警示、超過 75 分鐘未更新血壓的提醒、警示時間與確認紀錄；重設可恢復原始合成資料。使用合成回放時，應先重設再手動加測或匯入。

本版是前端規則型 **simulation/playback**，不是即時連接院內資料庫、沒有經驗證的 XGBoost 預測、不會自動建議 UF 或處置。臨床低血壓應依院內 SOP 評估。正式服務需院內資料介接、受控後端、身分權限、追溯性測量時間、資料新鮮度與版本管理、院內驗證與合法性評估。

## v0.9 雙檔合成 CSV 匯入（護理長示範）

1. 於網站開啟「雙檔匯入」。
2. 將 A「透析療程」與 B「逐次血壓／UF」分別匯入，或按兩側「載入合成範例」。
3. 確認自動欄位對應並檢視前 5 列。廠商欄位名稱不同時，可用下拉選單手動指定。
4. 按「① 檢查欄位與資料品質」，確認阻擋錯誤為 0。
5. 勾選「全部為虛構、無真實病人資訊的合成資料」，再按「② 整批載入合成看板」。
6. 回「床位總覽」查看相應日期／班別。新版會整批替換既有合成資料，重新整理網頁即回復預設資料。

**限制：** 公開 GitHub Pages 不可上傳真實電子透析紀錄，即使檔案使用 P001／S001 等假名化格式也不代表已經不可識別。匯入目前僅在本機瀏覽器記憶體運作，沒有院內後端、權限管理或永久儲存，也不訓練 XGBoost。Excel .xlsx 請由資訊室另存為 UTF-8 CSV；系統目前每檔最多 1 MB／5000 列，且示範看板只支援**同日完成的療程**。真正跨午夜療程須由院內後端使用完整時區時間戳記處理。

### 重要資料約束

- A 必須含：`patient_id, session_id, session_start, session_end, shift_code, bed_id, session_type, pre_sbp`。
- B 必須含：`session_id, measured_at, sbp, dbp, hr, ufr_ml_kg_h`。
- 完整時間格式示例：`2026-11-23T12:30`（合成示範採一致的本地時間）。正式介接必須確定時區。
- UFR 只接受 `mL/kg/h`，若原始廠商檔提供 `mL/h`，**不得直接改名對應**，需由資訊室確認體重來源與公式後轉換。
- 只有成功通過所有阻擋檢查的資料能整批匯入；不允許部分匯入。警告項目需人工確認。
- 匯入看板的患者 CAN 與歷史 IDH 為合成欄位。測量紀錄中的「測量原因」會保留以辨識異常加測。

## v0.9 護理長操作模式

GitHub Pages 為 **合成資料示範**，不要求護理長安裝 Python。

1. 開啟首頁「床位總覽」，先選日期／班別（週一三五第三班即夜班）。
2. 觀看常規監測／加強監測／高注意／已發生異常摘要及優先評估名單。
3. 點床位或優先清單的「查看」，進入當次 Session 的 BP、UFR、CAN 與歷史 IDH。
4. 必要時登錄異常加測，按「更新預警」；依院內 SOP 評估後，選處置並按「確認提醒與處置」。
5. 按「加入處置後追蹤量測」，輸入再次量測的時間與血壓，再新增該筆紀錄。
6. 開啟「品質報表」，檢視合成療程數、已記錄低血壓、護理確認及緊急透析數。
7. 「資訊室／模型說明」僅供技術團隊，GitHub Pages 不執行 XGBoost；正式模型應由院內受控伺服器運作。

**限制：** 所有護理確認及加測只儲存在當前頁面記憶體，重新載入會消失，尚未有登入、長期儲存及醫院 HIS 介接。公開站點禁止輸入真實病人資料。風險分類為示範規則，並非已訓練或校準的低血壓預測機率。

## XGBoost v0.7 建模

新增 `ml/train.py`、`ml/requirements.txt`、`ml/test_train.py`，以研究工作站或院內核准環境執行。靜態 GitHub Pages **不能自行執行 Python/XGBoost 模型**；尚未部署臨床推論 API。

### 1. 安裝與合成測試

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r ml/requirements.txt
python ml/train.py synthetic --out demo
python -m unittest discover -s ml -p 'test_*.py'
python ml/train.py train --sessions demo/sessions.csv --vitals demo/vitals.csv --out demo/output
```

Windows 啟用虛擬環境請改用 `.venv\Scripts\activate`。模型 JSON、校準參數、特徵清單與 metrics JSON 儲存在 `demo/output/`。所有合成資料與衍生成績只能用作流程驗證；不能推論臨床模型效能。若某個時間切分沒有陽性事件，訓練程式會停止，而不虛構結果。

### 2. 院內資料格式

`sessions.csv`（**每次透析一列**）：
```text
patient_id,session_id,session_start,session_end,session_type,pre_sbp,idh_prev10_routine,idh_prev10_all,can_status,dm
```

`vitals.csv`（**每次血壓量測一列**）：
```text
session_id,measured_at,sbp,dbp,hr,ufr_kg_h
```

- 時間戳記採完整本地日期時間（例如 `2026-11-23T10:00:00+08:00`，且整批需一致），不可只有 10:00。
- `session_type`：`routine`、`extra`、`urgent`、`inpatient`；第一版只以 `routine` 訓練。
- `can_status`：`confirmed`、`suspected`、`unknown`、`no_evidence`；糖尿病不能當作已確診 CAN。
- `idh_prev10_routine`、`idh_prev10_all`：**必須只用預測時間點之前已知的歷史療程**計算，不得從全部資料事後回填。
- 不以床號作為預測特徵；病人跨床位透析由 Patient ID 追蹤，單次療程血壓由 Session ID 連結。
- 常規一小時 BP，異常時不規則加測，保留測量及事件原始時間戳記。
- 最好另外提供加測原因、處置與其時間、UF 調整時間、療程結束原因、實際資料寫入時間、病人是否症狀性低血壓，以支援後續嚴格驗證。

### 3. 研究標籤及評估

只對當下 SBP ≥90、尚未發生 IDH 的療程量測時間點建模。標籤為**接下來 60 分鐘內首次「有紀錄」SBP <90 mmHg**。不足 60 分鐘觀察期者排除，已發生第一次低血壓後的時間點不作為新發事件。若提前處置或提前終止造成標籤不可判定，正式研究應另行處理 censoring/competing events。

依日期與療程作時間外切分（訓練／驗證／測試），使用驗證資料擬合機率校準、僅在測試資料評估。輸出 AUROC、AUPRC、Brier 分數、測試療程數與人數。**仍需補充病人群聚 bootstrap、病人外部驗證、IDH 事件層級敏感度、預警提前時間、模型校準曲線與預警負擔**，才能評估是否值得臨床試行。

### 4. 資安及臨床限制

請勿將院內病人資料、輸出的真實模型與內部報表提交公開 GitHub。院內推論 API 應具有身份驗證、授權與稽核。所有臨床預警均依院內 SOP；XGBoost 或本示範網頁不能直接控制 UF、藥物或輸液。模型完成後還須由院內 IRB、資安、臨床品質及醫療器材法規單位評估。

## 排班與床位架構

- 週一／三／五：第一、第二、第三班（第三班就是夜班）。
- 週二／四／六：第一、第二班。
- 週日預設無常規透析；緊急或臨時透析使用非排程時段。
- 同一床在不同班別可安排不同病人；以 Patient ID、Session ID、實際日期時間建立關聯。
- 急性非排程透析納入病人歷史及獨立資料集，**不可未經驗證直接套用常規 XGBoost 模型**。
